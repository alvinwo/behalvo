Date: 2026-09-25

Scope: diagnose the Node 22.19 verification failures on the published monitored-actions head and verify only the affected files on Node 22 and Node 24. The controller owns the complete verification run, so this investigation did not rerun the full suite.

## Failure evidence

The bounded full reproduction was:

```sh
npm exec --yes --package=node@22.19.0 -- node --test --test-timeout=60000 tests/*.test.mjs
```

It exited after 65.9 seconds rather than hanging indefinitely: 1,054 tests, 1,029 passed, 19 failed, 1 cancelled, and 5 skipped.

Three failures retained their expected safe stdout but received Node 22's experimental SQLite warning on stderr. Each child process imported `dist/index.js`; the barrel eagerly loads `node:sqlite` even though these probes exercise only the Keychain or native-messaging boundary. The empty-stderr and private-error non-leakage assertions were not relaxed.

The other failures came from `tests/us-visa-observation.test.mjs`. Its first test passed, then the next two initial portal fetches failed. Cleanup skipped by the failed test left the fixed port occupied, producing the remaining `EADDRINUSE` cascade and the file-level timeout.

The minimal RED probe was:

```sh
timeout 20s /root/.npm/_npx/992a19d7d9bf36d4/node_modules/node/bin/node \
  --test --test-timeout=12000 \
  --test-name-pattern='compiled synthetic page observation|compiled page metadata drift' \
  tests/us-visa-observation.test.mjs
```

On Node 22, the first test passed and the second failed with `TypeError: fetch failed`. The second test passed alone under Node 22, and the pair passed under Node 24. This isolated stale HTTP connection reuse across sequential fixed-origin server instances in Node 22's built-in fetch implementation.

## Fix

The synthetic portal now sends `Connection: close` on every response. This prevents the compiled-browser fixture from reusing a pooled connection after one fixed-origin server closes and another starts on the same port.

The three child-process probes now import their exact compiled modules:

- `dist/secrets/keychain.js`
- `dist/browser/native-host.js`

This avoids loading unrelated SQLite code while keeping the exact empty-stderr, safe-error, and raw-error non-leakage checks.
